# DRCE-LOC — апробация на OpenCV/C++

Реализация алгоритма из статьи:
Zhu Y. et al. "A Low-Delay Dynamic Range Compression and Contrast Enhancement
Algorithm Based on an Uncooled Infrared Sensor with Local Optimal Contrast",
Sensors 2023, 23, 8860.

## Файлы
- `drce_loc.hpp` / `drce_loc.cpp` — класс `DRCELOC`, шаги 1–8 алгоритма (Fig. 2 статьи).
- `main.cpp` — демо: загрузка изображения (или синтетическая 14-битная сцена),
  прогон алгоритма, сравнение с линейным AGC и CLAHE, метрики RMS/Entropy/Tenengrad
  (Section 3.1 статьи), сохранение промежуточных слоёв (dbg_*.png) для отладки.

## Сборка

### Вариант 1: напрямую
```bash
g++ -O2 -std=c++17 main.cpp drce_loc.cpp $(pkg-config --cflags --libs opencv4) -o drce_loc_demo
```

### Вариант 2: CMake
```bash
mkdir build && cd build
cmake ..
make -j
```

## Запуск
```bash
./drce_loc_demo путь/к/ик_кадру.png     # 8/16-бит, одноканальное
./drce_loc_demo                          # без аргумента — синтетическая тестовая сцена
```

## Ключевые параметры (DRCELOC::Params), соответствие статье

| Поле              | Формула статьи | Рекомендация статьи      |
|-------------------|----------------|---------------------------|
| blockRows/Cols    | X, Y (Step 1)  | блок ≈ 64×64 px            |
| bias              | Bias, Eq. 1    | 128–384                    |
| delta2            | δ², Eq. 2–3    | ≥ (M/X)·(N/Y)               |
| guidedRadius/Eps  | w, ε, Eq. 4    | окно 5×5 (radius=2)        |
| lambda            | λ, Eq. 5       | 128–384                    |
| k1                | k1, Eq. 6      | 1.0                        |
| k2                | k2, Eq. 6      | 0.2–0.7                    |
| gLow/gHigh, dde   | Eq. 7–8        | не заданы явно в статье — см. комментарий в drce_loc.hpp |

**Важно:** `normalizeInputTo255=true` по умолчанию — входные данные (даже 14/16-бит)
линейно нормализуются в диапазон 0..255 перед блочной статистикой, т.к. диапазоны
Bias/λ (128–384) из статьи заданы именно для этой шкалы. Без этого шага параметры,
подобранные авторами, не переносятся напрямую на сырые данные АЦП.

## Известные упрощения относительно статьи
1. **Eq. 7 (шумовая маска детального слоя)** — статья ссылается на внешний
   источник для точного вида функции и не приводит её полностью. Реализована
   типовая интерпретация принципа "меньше гейн в однородных зонах, больше —
   в детализированных", управляемая параметрами `gLow`/`gHigh`.
2. **Aппаратные оптимизации FPGA (Section 3.2)** — использование 16 из 25
   соседей в окне guided filter, LUT для экспоненты, фиксированная точка —
   не воспроизведены, т.к. это чисто hardware-специфичные оптимизации,
   не влияющие на результат при software-реализации в float.
3. Разделимость Gaussian upsampling (Eq. 2–3) реализована через `cv::gemm`
   (см. комментарий в `drce_loc.hpp`) — даёт точный (не приближённый)
   результат формулы, но быстрее наивного O(M·N·X·Y).
